# Darsi (درسي) — notes for Claude Code

Darsi is a serious upskilling PWA for school and university teachers (and their students) in developing countries. It covers AI, IoT and cyber security, in English and Arabic (RTL and LTR). It runs on Firebase now, with Capacitor for Android/iOS later.

## Layout
- `packages/design-system`: @darsi/design-system (tsup; tokens.json → CSS/TS/Tailwind; 45 RTL-aware components). Build it first: `npm run build -w @darsi/design-system`.
- `apps/web`: Vite 8 + React 19 + TS 6, react-router 7, vite-plugin-pwa, Capacitor 8, firebase 12, exceljs, pptxgenjs.
- Docs: `README.md` covers the concept and the why (brand voice; logo from `packages/design-system/assets/logos`). `TECHNICAL.md` is the technical reference: architecture, data model, rules, functions, caching, sync, CSS, tests, budget. Keep it current when you change those.
- `functions/`: Cloud Functions v2 (Node 22, region europe-west1): org requests and approval, invite codes, bulk member creation with random passwords, role changes, password reset, the progress → summary trigger.
- `firebase/`: firestore.rules, storage.rules, firestore.indexes.json. `firebase.json` at the root holds hosting, emulators and headers.
- Content: `apps/web/public/content/units/*.json`. Kits (PDF/PPTX) are generated by `apps/web/scripts/build-kits.mjs`.

## Conventions
- Use npm 11 (`npx -y npm@11.13.0 install` if npm 10 crashes with "edgesOut").
- Pin dependency versions that are at least two weeks old.
- Arabic text: never use "·" as a separator (it reads as Arabic zero). Use "،" or the i18n key `common.sep`.
- The app is light theme only. Do not add dark mode.
- Custom claims {role, orgId} are set only by Cloud Functions. Roles: learner, student, teacher, orgAdmin, superadmin.
- Username logins map to `<username>@users.darsi.app` (in `auth/api.ts` and `functions/src/passwords.ts`; keep the two in sync).
- Commit to git only when the user asks.

### Next steps, in order
1. Done: `src/admin/SuperAdmin.tsx` (/super), `src/admin/Teach.tsx` (/teach, /teach/:uid via `TeachPerson`), `src/org/OrgScreen.tsx` (/org). Pass names into `t()` through `isolate()` from `i18n` (the plain-text `<bdi>`).
2. Done: `App.tsx` is AuthProvider > StoreProvider (key = uid or "guest") > I18n > Router.
   - Each account has its own local store (`darsi:state:<uid>`); guests keep `darsi:state`. An account created in the last 10 minutes takes over the guest's progress. Any other account takes only the guest's settings.
   - Guests are people who chose "Continue without an account" (`state.guest`) or who onboarded before accounts existed.
   - The staff routes (/org /admin… /teach… /super) skip the onboarding gate; the learning routes don't.
   - Signing in remounts the router (new store key), so the account screens' own `nav()` after sign-in never runs. `SignedIn` in App.tsx redirects instead and keeps `?org=1` → `/org?request=1`.
3. Done: cloud sync in `src/state/sync.ts` (`useCloudSync(uid)`, called in App.tsx `Routed`). Progress goes to `users/{uid}/progress/{lessonId}` {lessonId, unitId, track, accuracy, xp, seconds, completedAt, competencies}; notes go to `users/{uid}/notes/{lessonId}` {text, updatedAt (ms)}.
   - Low data and battery: no live listeners, no polling. It reads both collections once per sign-in, and again on the `online` event if that read only reached the offline cache. It writes only what changed, and Firestore's offline queue carries the writes.
   - Merge (`mergeRemote` in store.tsx): the newer copy wins, by `completedAt` for lessons and by `notesAt` (local edit time) vs `updatedAt` for notes. A note saved before sync has no time and loses to the cloud. A lesson first seen from the cloud counts toward its own week (streaks).
   - Push (`toPush`): writes entries the cloud lacks or has older. Until a server read succeeds, it writes only what was finished this session, so a stale phone never overwrites newer work. Older results without unitId/track get them from the content files.
   - Not tested against a backend (no JDK 21 for the emulators); `tests/sync.test.tsx` covers the rules and the hook with Firestore mocked.
   - "Reset progress on this device" only clears the local copy: the next sign-in brings the cloud copy back, and the rules forbid deleting progress.
