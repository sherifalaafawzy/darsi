# Labs for the AI agents and AI security tracks

A hand-over for course writers: what each app teaches, what counts as finishing it (the lab step's done mark), and the numbers it shows. All of them were measured on 2026-10-28 with Darsi Tiny v1 (`tools/tinylm/MODEL_CARD.md`). Numbers from a PC are fast; an old phone is slower, and the apps say which is which.

The apps that run Darsi Tiny show its one-time download first (2.8 MB, the model, tokenizer and the school's data) and fetch it only when the learner presses a button. "Save all labs for offline" saves the apps but not the model: each needs one run while online. Every tool is a simulation over a made-up school world; nothing is ever sent.

## AI agents (`agents-how`, `agents-practice`)

| App | Level | Teaches | Done when | What it shows |
|---|---|---|---|---|
| `agentloop` Inside an agent's loop | 1 | Request → plan → tool call → result (written by the app, not the model) → answer, one step at a time or run to the end. "What Darsi Tiny sees" shows the raw prompt. 7 example requests per language, or type one | 3 different requests answered | Tokens written, seconds and tokens a second on this phone (~200/s on a PC); the two-step trip calls route then weather |
| `tools` How an agent picks a tool | 2 | The ten tools as switches, and the tools line the model reads. A tool turned off, a request no tool covers ("I can't"), a missing detail (it asks, and you answer). Every call gets an argument check | 3 of 4 outcomes seen (used a tool, tool off, can't, asked) | Mistakes it really makes: "9Z" copied as `9C`; "Explain the term malware" → `{"term":"the term malware"}`; the capital of France → "I can't", but "What is…" guesses the glossary |
| `planner` Plan in steps | 2 | The plan line, and goals that need two tools, the second from the first's result (route → weather; glossary → library; timetable → reminder). Guess the tools first, then compare. Chips show where each copied word came from: your request, a result, or nowhere | 2 different two-step goals answered | When step one fails it carries on regardless: on Saturday ("no school") it still sets the reminder `6B: 6B` |
| `memory` An agent's memory | 3 | The 384-token window as a bar, by who wrote each part (counted with the real tokenizer). Keep everything, drop the oldest, or keep notes; window 128–384 | A turn has fallen out, and a turn has finished with notes | Keep everything: the 4th answer is cut off. Drop the oldest at 128: "yes" gets a greeting (the question fell out) and "tomorrow" is lost. Keep notes: all 7 messages work. Big cloud models read ~128,000 tokens (labelled typical) |
| `approve` Ask before acting | 2 | Permission levels: read only, ask first, allowed. A message needs the model's question and your yes, checked in code (the check can be switched off to see why it matters) | One message sent after your yes, and one action blocked or refused | «نعم، أرسلها.» on its own makes the model invent a message; the code check blocks it ("no one was asked") |
| `teach` Teach the agent a new tool | 3 | Fine-tuning on the phone: a new `bus` tool from 16 examples (8 per language), 15 steps. Mix in 0, 16 or 48 old conversations. Loss chart, time left, Stop. The result is kept on the phone (1.6 MB) and can be switched on and off | One full run finished and tested | 8 bus requests on new villages plus 8 old skills. Before: 0/8 and 8/8. Mixing in 0: 7/8 new but 1/8 old (it forgets); 16: 7/8 and 5/8; 48: 5/8 and 8/8. On a PC 38 s to 2 min 16 s; an old phone about 3, 6 or 11 minutes (estimated) |
| `evals` Test an agent | 3 | A test set of 32 requests (English/Arabic × trained/new wordings), scored like the model's own evaluation; the failures listed; can test the model from `teach` too | A full run of 32 | 29/32 (91%): trained wordings 16/16, new 13/16; right tool 31/32; about 2.5 s on a PC |
| `team` A planner and a checker | 3 | Roles: the planner is the model; the checker (5 rules in code), the runner and you are not, and the app says so. A reminder waits for you; a message passes after your approval | The checker has stopped a bad call, and an action has run after your OK | Weather passes; 9Z→9C, a garbled reminder, 25:00 and the Saturday reminder are stopped. With the checker off, the bad reminder is set |
| `costs` What an agent costs | 2 | Tokens, time, data, money and battery: Darsi Tiny on the phone against a big cloud model on 2G/3G/4G. Measured values and typical ones are labelled; the learner sets the data price and requests a day | A request measured and one comparison setting changed | Weather request: Tiny 58 tokens read, 50 written, 0.2 s on a PC (~1.3 s on an old phone). Cloud: ~2,500 tokens, 18 KB, 5.4 s on 2G, ~$0.008. A month at 20 a day: 10.8 MB for the cloud against 2.8 MB once; the cloud passes Tiny's download after ~154 requests |

## AI security (`aisec-apps`, `aisec-models`)

Defence first: every attack is a harmless simulation inside the pretend school, and every takeaway leads with the defence.

| App | Level | Teaches | Done when | What it shows |
|---|---|---|---|---|
| `inject` Hide an order in the data | 2 | Prompt injection on Darsi Tiny: an order hidden in a note, a book title or a village name in a tool result. It ignores the wordings it was trained on; new wordings and places slip into the answer, and a title that fakes an approval question can get a message sent. Then the defences in code: keep data apart from instructions, give only the tools the task needs, ask in code before any message | Any run | The outcome of each attack: ignored, leaked, sent, blocked; the loop with what the model was shown |
| `guardrails` Rules around the model | 2 | A keyword filter, an output check and a check on the action in code. The filter catches the plain scam but misses the reworded one, in both languages; the action check blocks a message nobody approved, however it's worded | A run | Each guard: stopped or passed; sent or held |
| `privilege` Least privilege | 2 | Pick the tools an agent gets for a task, then replay a set of tampered results and count what it could have done | The attack set has run | With no tool that acts, 0 harmful actions; give it `send_message` and an injection can act. Over-granted tools listed |
| `redteam` Test a chatbot | 3 | A bank of 8 mild requests it should refuse (both languages, trained and new wordings): score, read the misses, add a rule in code, run again. How to write a red-team report | The bank has run | Refused 6/8 in English, 7/8 in Arabic; with the rule 8/8. A report table: what, tried, got through, how bad (1–3) |
| `poison` Poisoned data | 2 | Flip some labels, train on the phone, watch accuracy fall; find the flipped points with a nearest-neighbour check, drop them and retrain | "Find the odd ones out" | Accuracy ~97% → ~93% with flips; nearly all flipped points found, plus a few honest borderline false alarms |
| `adversarial` Pictures that fool a model | 3 | Small pixel changes (a gradient-sign step) flip a small shapes network; the two pictures look the same. Training with such pictures makes it harder | Train (adversarial training) run | Test accuracy ~89%; a confident answer flips with 6–8 pixels; at 10 pixels, attacks that fool it fall from ~14/18 to ~7/18 after training |
| `leak` A model that remembers too much | 3 | A tiny model memorises a made-up private line and repeats a made-up card number; privacy noise closes the leak and lowers a membership-inference guess, at a cost in usefulness | Privacy closes the leak | Attacker's guess 100% → ~46%; usefulness 44% → 28% (English) |
| `watermark` Spotting generated text | 2 | A green-list watermark: the generator prefers "green" words, the detector counts them. Editing weakens it. Detectors make mistakes, so a score is never proof of cheating | Text written and checked | Watermarked text 6/6 green, z ≈ 2.45, flagged; a natural sentence near chance (now and then a false alarm, shown honestly); 2–3 edits erase the signal |
| `supplychain` Is this the real model? | 2 | A file's SHA-256 fingerprint, a changed file whose fingerprint no longer matches, and a signature (ECDSA P-256 keys made on the phone) that tells you who published it. Real WebCrypto | A scenario verified | One changed byte flips ~145 of 256 bits; Darsi Tiny's real files and sizes (model.bin 2,998,448 bytes) |
